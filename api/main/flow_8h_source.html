27/*
28 * A grain can be marked as invalid for multiple reasons. For example, an input application may have
29 * timed out before receiving a grain in time, etc. Writing grain marked as invalid is the proper way
30 * to make the ringbuffer <move forward> whilst letting consumers know that the grain is invalid. A consumer
31 * may choose to repeat the previous grain, insert silence, etc.
32 */
